# SeedDrift benchmark 方案（草案）

目标：用可复现的数字回答“SeedDrift 强在哪、弱在哪”，和现有方法放在同一把尺子上比。
原则：测试集与开发、调参严格分开；每个数字都能由 `bench/` 下的脚本在新机器上一键复现。

## 1. 要回答的问题

| # | 问题 | 对应模块 |
|---|---|---|
| Q1 | 单基因组筛查：能否找出跨界、跨门的外来基因（来自哺乳动物、原核、病毒），假阳性多少 | `genome`（single.py） |
| Q2 | 供体判定：给出的供体类群对不对 | single / donors |
| Q3 | 多基因组扫描：转移事件的召回率、精确率，以及受体节点放得准不准 | scan / reconcile |
| Q4 | 各项改进是否有用：重复过滤、深度检索、建树验证、结构检索、组成、上下文 | 消融 |
| Q5 | 抗伪迹能力：污染、重复蛋白、旁系同源、长枝吸引 | 负对照 |
| Q6 | 速度和规模：每个基因组用多少时间、资源，规模扩展如何 | 全流程 |

## 2. 测试集

### A. 模拟数据（真值完全已知）
- 现有的 `seeddrift simulate` 只在家族和树的层面模拟，不够。需要补序列层面的模拟：
  - **工具：** Zombi（基因组演化加 HGT）或 ALF / AliSim，生成序列并保留真实的转移记录。
  - **场景：**
    - 近缘转移和跨门转移各占一部分；
    - 加入未采样供体；
    - 古老转移；
    - 速率异质性和长枝吸引；
    - 模拟污染 contig。
- 用途：Q3、Q4 的主力，以及各参数下的召回率曲线。

### B. 真实阳性：文献证据充分的 HGT

| 受体 | 外来来源 | 已知阳性 | 说明 |
|---|---|---|---|
| 溶组织内阿米巴 *Entamoeba histolytica* | 细菌 | 基因组论文和后续的系统发育复核中报道的 LGT 基因列表 | Q1：真核受体、原核供体 |
| 蛭形轮虫 *Adineta vaga* | 细菌、真菌、植物 | 基因组论文中的外来基因集合 | 外来基因比例高 |
| 果蝇等昆虫 | *Wolbachia* | 核基因组中的 *Wolbachia* 插入片段 | 有基因组位置可以核对 |
| 嗜肺军团菌 *Legionella pneumophila* | 真核宿主 | 已知的类真核效应蛋白（锚蛋白、F-box、激酶等） | Q1：细菌受体、真核来源 |
| 肠杆菌目 | 其他细菌、噬菌体 | SPI-1/2、LEE 等已知毒力岛，以及原噬菌体 | Q3（已有 18 个基因组的例子） |
| 植物、真菌、昆虫中经典的单基因 HGT | 各类 | 每个都有独立系统发育证据的案例 | 作为“难例” |

具体的基因列表要从原文补充材料中整理，每条记录写明出处（DOI 加表号）。整理完才算可用。

### C. 真实阴性和伪迹（专门考验假阳性）

| 类型 | 内容 | 期望结果 |
|---|---|---|
| 核心单拷贝基因 | 核糖体蛋白、BUSCO 基因 | 判为本谱系 |
| 被推翻的 HGT | 人类基因组“细菌来源基因”（采样不足）、缓步动物大规模 HGT（组装污染） | 不应给出高置信判定 |
| 人工污染 | 往真核组装里掺入细菌 contig | 识别为污染 contig，而不是 HGT |
| 重复蛋白 | 锚蛋白、LRR、TPR、卷曲螺旋、串联重复的假 ORF | 判为 repeat，不给供体 |
| 参考库自身污染 | 例如此前发现的 *Thelohanellus* 案例 | 支持物种数为 1 时降级 |

## 3. 对比方法

| 类别 | 工具 | 对比的问题 |
|---|---|---|
| 相似性 / Alien Index | HGTector、AvP、Alienness 类的 AI 流程、DarkHorse | Q1、Q2 |
| 系统发育调和 | ALE、GeneRax / AleRax、RANGER-DTL、ecceTERA | Q3 |
| 组成方法 | 基于 GC、密码子偏好的方法，以及 IslandViewer 类的基因组岛预测 | Q3（近期转移） |
| 内部基线 | 只用 DIAMOND 和 AI 阈值（不过滤、不建树） | Q4 消融的起点 |

所有工具使用同一个参考库、同一套输入，并记录版本和参数。

## 4. 指标

- **检测：**
  - 基因层面的精确率、召回率、F1；
  - 整条 PR 曲线和 AUPRC，因为各工具的阈值不同，用整条曲线比较；
  - 高置信档位下的精确率，这个指标对实际使用最重要。
- **供体：** 供体类群的准确率，在门、纲、目各层级分别统计。
- **事件（Q3）：** 事件召回率、受体节点准确率、深度分层的召回率。
- **伪迹：** C 组中每一类的误报率。
- **资源：** 墙钟时间、CPU 小时、GPU 小时、内存，按基因数和参考库大小分别统计。
- **统计：** 用自助法给出置信区间；工具两两比较用配对检验。

## 5. 消融（Q4）

以完整流程为准，每次只去掉一项：
1. 重复过滤（Pfam / 串联重复 / 卷曲螺旋）；
2. 深度检索（不屏蔽重复的 DIAMOND）；
3. 建树验证；
4. 结构检索；
5. 组成、基因组上下文、污染 contig 检查；
6. 参考库规模：均衡库对比广覆盖库；
7. 多基因组模式中的旁系同源拆分、gain 事件、分子钟。

## 6. 实施步骤

1. 整理 B、C 两组金标准，在 `bench/goldstandard/` 下建 TSV 表（基因 ID、受体、供体类群、证据、出处）。
2. 写 `bench/run_benchmark.py`：统一跑 SeedDrift 和各对比工具，输出指标表和图。
3. 补序列层面的模拟器，即 A 组。
4. 先跑一轮基线，看清现状，再决定优先改进哪里。
5. 冻结测试集：之后的调参只用单独的开发集。

## 7. 现在已知的风险

- 金标准本身有噪声：文献里的 HGT 判定也会有错，需要记录证据强度，按强度分层统计。
- 单基因组筛查只看相似性，对近缘转移原理上就不敏感。这一点应在报告中如实写出，不要回避。
- 对比工具的安装和运行可能会花不少时间，比如 HGTector 需要自己的数据库，ALE 需要 bootstrap 树。
