# W13 step 1: a wider catalogue snapshot (stage w13_catalog) and the census counted twice

- Stage `w13_catalog` (`ci/stages/rel/w13_catalog.py`, rule in `ci/rules/rel_w13.smk`; kind rel_corpus, the select
  lock): the ENA portal's assembly records (metadata only) of bacteria and archaea at the levels complete genome and
  chromosome and of viruses at complete genome, one query per catalogue, accepted only when the answer has every row the portal
  announces (the portal answers a row per version of an assembly); canonical TSV, one record per accession (the highest
  version, then the latest update), sorted, with the rows and the older versions dropped in the lock in the content store and the run, and
  `data/rel_w13/catalog/lock.yaml` with query, fields, records, sha256 and the fetch time, plus the counts of every
  assembly level per taxon. Gate G4_rel_w13_catalog. No sequence is downloaded.
- Stage `w13_census` takes `catalog_from` (a passed run of w13_catalog, or `this run`): the same count a second time on
  the wider snapshot, with the selection's rules (the exclusions by full lineage and the extra lists, a virus's host by
  lineage, a virus without a checkable host left out, a genus and a species for prokaryotes), corpus genomes counted as
  in the corpus, records the sealed check refuses left out unnamed, environmental samples counted apart; the report and
  its page set both counts side by side and say how the two snapshots differ. Profile `rel-dev-w13-catalog-i1` runs both
  stages in one select-lock run (it contains the census of `rel-dev-w13-census-i1`).
