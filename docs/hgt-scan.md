> 这份文档说明多基因组 HGT 扫描（`seeddrift prepare / scan / donors / structure`）的方法与结果，沿用 SeedDrift 的前身 hgtscan 的写法。这项功能只有命令行，是原型；需要另行安装 OrthoFinder 和 IQ-TREE。示例脚本在 `examples/`。单基因组筛查、服务和网页见仓库根目录的 README。

# 多基因组 HGT 扫描（原型）

**输入**：物种树、每个基因家族的基因树（ML 树 + bootstrap 树）、基因坐标、移动元件注释，可选 CDS 组成（GC、GC3）。
**输出**：每个候选转移事件的受体分支、`P(HGT)`、供体候选排序及各自概率（供体在数据集之外时报为 `unsampled`），以及逐项证据。

支持原核、真核以及两者混合的数据集。依赖只有 Python ≥ 3.9 和 numpy。

候选来自三个来源，各用一套独立校准的模型打分：

- **tree**：DTL 调和发现的拓扑不一致。供体在数据集内。
- **clock**：基因树拓扑一致，但跨某个物种形成节点的基因分化明显比物种分化年轻，说明两个谱系分化后交换过这个基因（v0.3 新增）。
- **gain**：家族（或其一部分）只在某个非根类群中出现，供体不在数据集内（v0.4 新增）。DTL 只会把它解释成“在该节点起源”。细菌近期 HGT 的大部分属于这一类。

```
多拷贝家族 ──在古老重复处拆成直系亚家族（物种重叠）──▶ 以下各步按亚家族进行
基因树样本 ──DTL 调和（按时间约束）──▶ f_T / f_opt ───────┐  tree 候选
            └─物种形成节点的分子钟检验 ─▶ z（全基因组背景）┤  clock 候选（谱系间交换）
基因坐标 ──▶ 受体侧插入（姐妹类群 + 外群）/ 上下文偏移 / 共转移 ├─▶ 分来源的逻辑回归 P(HGT)
移动元件 ──▶ 邻近得分（扣除基因组背景）                  │    softmax ─▶ 供体排序
基因树枝长 ──▶ 近期性                                    │    外群插入 ─▶ clock 的方向
家族分布 ──gain/loss 简约──▶ 获得节点 ────────────────────┤  gain 候选（供体未采样）
CDS 组成 ──▶ GC/GC3 偏离（按受体枝年龄折减）               │
contig 组成 ──▶ 污染检查（真核）                         ┘
```

## 快速开始

```bash
PYTHONPATH=$PWD bash examples/simulate_demo.sh
```

脚本依次执行：
1. 模拟原核、真核、混合三类数据，每类一个训练集、一个测试集。
2. 扫描所有数据集。测试集额外用无噪声的真实基因树扫一遍（oracle）。
3. 在训练集上分来源校准权重。
4. 在测试集上分别用默认权重和校准权重评估。

8 核大约 30 秒。结果写在 `examples/demo/` 下。

## 用自己的数据

```bash
python3 -m seeddrift scan \
  --species-tree species.dated.nwk \
  --gene-trees gene_trees/ \
  --genes genes.tsv \
  --me mobile_elements.tsv \
  --species-meta species.tsv \
  --composition gene_composition.tsv \
  --model demo/model.calibrated.json \
  --collapse 95 \
  --out results/ --threads 8
```

| 输入 | 格式 | 怎么准备 |
|---|---|---|
| `--species-tree` | 有根 Newick，叶名为物种 ID；**枝长最好是时间单位** | 核心基因串联树或 ASTRAL 树，用外群定根，再用 LSD2、MCMCTree 或 `ape::chronos` 做时间校准 |
| `--gene-trees` | 目录，每个家族一个或多个文件，文件名前缀为家族名；第一棵是 ML 树，其余作为 bootstrap 样本 | `iqtree2 -s OG0001.faa -m MFP -B 1000 --wbtl --prefix gene_trees/OG0001`，会自动读取 `.treefile` 和 `.ufboot` |
| `--genes` | TSV：`gene_id species family contig start end` | GFF 坐标加 OrthoFinder orthogroup；`gene_id` 必须与基因树叶名一致 |
| `--me` | TSV：`species contig start end type` | 原核：ISEScan、geNomad、IntegronFinder、tRNAscan-SE；真核：EDTA 或 RepeatMasker |
| `--species-meta` | TSV：`species domain`（`prok` / `euk`） | 混合数据集必需；也可以用 `--domain` 统一指定 |
| `--composition` | TSV：`gene_id gc gc3`（可选） | 由 CDS 计算；`prepare` 的 `composition` 步骤会生成 `gene_composition.tsv`。没有这项时，组成特征为 0 |

主要参数：
- `--dated auto|on|off`：只允许时间上共存的枝之间发生转移。默认 `auto`，即物种树有枝长就启用。物种树枝长不是时间单位时，用 `off` 或先做时间校准。
- `--clock-z 2.5`：分子钟候选的阈值，单位是节点特异的稳健标准差。设为 0 关闭。这一步需要基因树枝长。
- `--costs 2,3,1`：重复、转移、丢失的代价
- `--bt 3`：每棵树随机抽取的最优调和数
- `--window 4`：synteny 窗口，单位是基因数
- `--min-freq 0.1`：报告事件的最低频率
- `--no-gain`：不生成 gain 候选，只保留 tree 和 clock 两类。
- `--split-paralogs 2`：平均每个基因组 ≥1.5 个拷贝的家族，在古老重复处拆成直系亚家族（亚家族名为 `<家族>.<k>`）。判断古老重复的条件是：两侧子树共有至少这么多个物种，且至少占较小一侧物种数的一半。设为 0 关闭。
- `--collapse 95`：把支持度低于阈值的基因树枝（以及长度近似为零的枝）收缩成多分叉，再按物种树贪心解开；这时用 ML 树代替 bootstrap 样本。**真实数据建议用 95**（IQ-TREE UFBoot），默认 0 表示关闭。它只消除没有支持的不一致，有支持的不一致会保留

## 从原始基因组准备输入（`prepare`）

`python3 -m seeddrift prepare` 从 Ensembl Genomes 下载基因组，生成 `scan` 需要的全部输入：

```bash
# 一次性安装工具（独立环境，不影响系统 Python）；用 ./seeddrift.sh install 装过的话，micromamba 在 .mamba/bin/micromamba
MAMBA_ROOT_PREFIX=~/mamba micromamba create -y -n hgt -c conda-forge -c bioconda orthofinder mafft iqtree diamond

python3 -m seeddrift prepare --genomes genomes.tsv --index species_EnsemblBacteria.txt \
  --workdir mydata --threads 9            # 工具默认从 ~/mamba/envs/hgt/bin 查找
```

`genomes.tsv` 有三列：`label`、`ensembl_name`、`role`。`role` 写 `outgroup` 的基因组用于给物种树定根。流程分六步，每一步都会跳过已完成的部分，中断后重跑会从断点继续：

| 步骤 | 做什么 | 输出 |
|---|---|---|
| `fetch` | 下载 `*.pep.all.fa.gz`、`*.cds.all.fa.gz` 和 `*.gff3.gz` | `raw/` |
| `proteomes` | 每个基因取最长蛋白。移动元件从注释中提取：转座酶、整合酶、噬菌体、重组酶、质粒复制子、tRNA | `proteomes/`、`gene_coords.tsv`、`mobile_elements.tsv`、`species.tsv` |
| `composition` | 每个保留基因的 CDS 的 GC 和 GC3（第三位点，不含终止密码子） | `gene_composition.tsv` |
| `orthogroups` | OrthoFinder（`-og`），兼容 v2 和 v3 | `Orthogroups.tsv`、`genes.tsv` |
| `genetrees` | 对 4–150 个基因的家族：MAFFT 比对，过滤缺失超过 50% 的列，IQ-TREE（LG+G4，UFBoot 1000，保留 50 棵 bootstrap 树） | `gene_trees/`、`alignments/` |
| `speciestree` | 最多 300 个单拷贝家族串联，IQ-TREE（LG+F+R4），外群定根，再用 MPL 转成带相对时间的树 | `species_tree.nwk` |

注意：
- 基因组从 Ensembl Genomes 下载；其他分区可以用 `--division fungi` 等切换。
- Ensembl 对 Prokka 注释的细菌基因组不提供 tRNA 特征，这些基因组缺少 tRNA 这一项。
- 移动元件按注释关键词识别，不如 ISEScan 或 geNomad 全面。
- MPL 时间化很粗略。如果有化石或速率校准，最好换成 LSD2 或 MCMCTree 得到的时间树。
- OrthoFinder 不支持含空格的路径，所以它和建树都在系统临时目录里运行，结果再拷回工作目录。

肠杆菌目示例（18 个基因组，外群为霍乱弧菌）的完整命令见 `examples/enterobacterales/run.sh`，结果见下文“真实数据”一节。

`prepare --tree-method fasttree`：基因树改用 FastTree（`-lg -gamma`）。CPU 用量约为 IQ-TREE 的 1/100；SH 型局部支持值乘以 100 写入，所以 `--collapse 95` 的含义不变。已有树的家族会跳过，因此可以中途从 IQ-TREE 切换过来。

## 外部供体检索（`donors`）

gain 事件的供体在数据集之外（`unsampled`）。`donors` 把这些候选基因与一个分类均衡的外部参考库比对，判断供体属于哪一类：哺乳动物、其他真核、各门细菌、古菌或噬菌体。

```bash
python3 -m seeddrift donors --workdir mydata --scan mydata/scan_calibrated --ref ref \
  --out mydata/donors --index species_EnsemblBacteria.txt --engine diamond --threads 16
```

| 步骤 | 做什么 |
|---|---|
| `reference` | 从 UniProt 参考蛋白组中按 NCBI 分类挑选：γ-变形菌每属 1 个；其他细菌、古菌、哺乳动物每科 1 个；其他真核每目 1 个；病毒每属 1 个。下载后合并成 `reference.faa`。分类优先用 NCBI taxdump（会读取 `https_proxy`），连不上时退回 EBI 上的旧副本，后者缺少近年新命名的类群 |
| `queries` | 取 P_HGT ≥ 0.6 的候选基因（默认只取 gain 事件），以受体所在的属（或更高一级）作为“自身类群” |
| `search` | 默认 DIAMOND `--sensitive`；也可选 MMseqs2（CPU，或 `--engine mmseqs-gpu`） |
| `classify` | 去掉自身类群的命中后，统计覆盖查询 ≥40% 的命中。计算 Alien Index（肠杆菌目内与目外最佳命中的 E 值对比），并取前 10 个外部命中按 bit 分加权，得到最可能的供体类群；同时标出哺乳动物命中 |
| `trees` | 对每个事件，取受体基因加最多 60 个外部同源序列（每属最多 3 个），用 MAFFT 比对、FastTree 建树（`--tree-method iqtree` 可改用 IQ-TREE）。供体类群取树上离受体基因最近的 5 个参考序列 |

输出：`donors_by_gene.tsv`、`donors_by_event.tsv`、`trees/<事件>.treefile`。

## 无外部同源基因的结构检索（`structure`）

`donors` 中“外部无同源”的事件，序列搜索已经无能为力。`structure` 换两条更灵敏的路线：迭代 profile 搜索，和预测结构后做结构比对。

```bash
python3 -m seeddrift structure --donors mydata/donors --out mydata/struct --ref ref \
  --model <esmfold_v1 模型目录> --mmseqs tools/mmseqs/bin/mmseqs \
  --target swissprot_pdb_v6.tar --foldseek foldseek --sprot uniprot_sprot.fasta.gz \
  --pfam <含 Pfam-A.hmm.gz 与 Pfam-A.hmm.dat.gz 的目录> --ncoils <ncoils 路径> --threads 16
```

需要另装 pyhmmer（`pip install pyhmmer`）和 COILS（bioconda 的 `coils` 包，提供 `ncoils`；找不到时跳过卷曲螺旋检测，并在日志中说明）。

| 步骤 | 做什么 |
|---|---|
| `queries` | 每个“外部无同源”事件取最长的蛋白作代表 |
| `profile` | MMseqs2-GPU 迭代 profile 搜索（3 轮，E ≤ 1e-5），比对 `donors` 的参考库，再按 `donors` 的规则分类 |
| `predict` | ESMFold（HuggingFace 格式，GPU，trunk 半精度）预测结构，记录平均 pLDDT；默认跳过 >1000 aa 的蛋白 |
| `pfam` | 标出代表蛋白的重复型区域，写入 `pfam.tsv`，分三类：<br>① Pfam-A 注释（pyhmmer，gathering 阈值）中的重复型结构域：类型为 Repeat / Coiled-coil / Disordered，或所在 clan 以 Repeat 家族为主（LRR、TPR、锚蛋白、β 螺旋桨等），53,275 个家族中有 2,695 个；<br>② 串联重复（`tandem_repeat`）；<br>③ 卷曲螺旋（`coiled_coil`） |
| `search` | Foldseek 比对 AlphaFold DB 的 Swiss-Prot 结构（`createdb` 可以直接读 tar）。默认先试 Foldseek-GPU，不可用时自动改用 CPU；`--cpu` 直接用 CPU |
| `classify` | 保留 prob ≥ 0.5、E ≤ 1e-3、覆盖查询 ≥ 40%、TM ≥ 0.5（同一折叠）的命中，去掉自身类群，前 10 个按 bit 分加权得出类群，并标出哺乳动物命中。之后做重复过滤，见下文 |

**重复过滤**（`classify` 中进行，结构命中与 profile 命中采用同样的规则）：

1. **重复型区域有三种来源：**
   - **Pfam。** 查询的 Pfam 注释很不完整，因为孤儿蛋白的重复单元本身高度分化，大多过不了阈值。因此还要扫描所有被命中的目标蛋白；目标蛋白（如人类锚蛋白）注释完整得多。
   - **串联重复。** 在 BLOSUM62 自比对矩阵的各条非主对角线（偏移 3–200）上滑动窗口打分，窗口约为一个重复单元（12–40 个残基）。窗口得分比按该序列自身组成算出的期望高 6 个标准差，就标为重复，两份拷贝都标。单纯的组成偏倚不会触发。
   - **卷曲螺旋。** COILS：窗口 28，`-w`（a、d 位与其他位同权），P ≥ 0.9。
   
   目标蛋白的三类区域缓存在 `repeat_targets.tsv`。
2. 一条命中在查询或目标上的比对区段，若 ≥ 50% 落在重复型区域，且序列一致度低于 40%，就判为重复驱动，不计入供体类群。一致度 ≥ 40% 的长比对是真同源，不是 profile 漂移，所以保留。
3. 前 10 个命中的 bit 分中，重复驱动的命中占一半以上时，整个事件标为 `repeat-like`，不给供体类群。否则剩下零星几条非重复命中，会给出没有意义的类群。

阈值在 *E. coli* K-12 全部 4,186 个蛋白及其打乱序列（保持组成）上校准：

| 检测 | K-12 | 打乱序列 | K-12 中比例最高的蛋白 |
|---|---|---|---|
| 串联重复，z = 6 | 2.6% | 0.05% | YbeQ（Sel1 重复）、CsgA（curlin）、YmdF / YciG（KGG 重复）、YegP（DUF1508 串联重复）|
| COILS，P ≥ 0.9 | 3.3% | 0.7% | ZapB、SlyX、Lpp、ZapA、PspB，均为已知的卷曲螺旋蛋白 |

z = 5 时打乱序列的误报升到 2.8%；z = 7 时开始漏掉 LRR 和五肽重复。

输出：`predict.tsv`、`pdb/`、`pfam.tsv`、`repeat_targets.tsv`、`hits.m8`、`structure_donors.tsv`，以及 `profile/donors_by_gene.tsv`（未过滤）和 `profile_nr/donors_by_gene.tsv`（过滤后）。

`structure_donors.tsv` 中与过滤有关的列：

| 列 | 含义 |
|---|---|
| `pfam` | 查询的 Pfam 结构域以及 `tandem_repeat`、`coiled_coil`，`*` 表示重复型 |
| `repeat_frac` | 重复型区域覆盖查询的比例 |
| `n_repeat_hits` | 被剔除的重复驱动命中数 |
| `top_group_all` | 过滤前的类群 |

## GPU 机器上的基准测试（A800 80GB，容器 CPU 配额 16 个超线程）

脚本：`bench/benchmark_gpu.py`、`bench/search_agreement.py`。

**同源搜索**：从 18 个基因组随机抽 1,000 条蛋白，对 1,842 万条蛋白的参考库搜索。

| 引擎 | 墙钟时间 | CPU 时间 | 有命中的查询 | 前 50 命中与 DIAMOND 的重合度 | 供体类群与 DIAMOND 一致 |
|---|---|---|---|---|---|
| DIAMOND `--sensitive` | **215 s** | 2,776 s | 965 | — | — |
| MMseqs2-CPU `-s 7.5` | 445 s | 6,347 s | 966 | 0.955 | 98.4% |
| MMseqs2-GPU | 597 s | 808 s | 966 | 0.957 | 98.1% |
| MMseqs2-GPU，参考库常驻显存（`gpuserver`） | ≈460 s（预筛 438 s） | — | 966 | 同上 | 同上 |

- 三种引擎的灵敏度相当。
- MMseqs2-GPU 对每条查询都要扫描整个参考库（无 k-mer 索引），耗时与“查询数 × 库大小”成正比，本例约 0.45–0.6 秒/条，全部 81,844 条蛋白估计需 8 小时以上。它适合少量、需要高灵敏度的查询，例如为结构预测生成 MSA，不适合几千条以上的批量检索。
- 建库都很快：MMseqs2 1 分钟，GPU 用的补齐库 2 分钟，DIAMOND 1 分钟。

**基因树**：在 IQ-TREE 最先完成的 508 个家族上比较。这些家族偏大，多为多拷贝家族。

| 指标 | 结果 |
|---|---|
| CPU 时间（分层抽样 32 个家族，中位 30 条序列） | IQ-TREE（UFBoot 1000）2,139 s，FastTree 22 s，相差约 96 倍 |
| 拓扑差异（标准化 RF） | 中位数 0.14 |
| IQ-TREE 中 UFBoot ≥95 的分支被 FastTree 推翻的比例 | 48 / 5,989（0.8%） |
| 收缩低支持枝后判出的转移（f_T ≥ 0.5） | IQ-TREE 2,053 个，FastTree 2,049 个，其中 1,170 个相同（57%）；69 个家族的判定完全一致 |

在这些大的多拷贝家族上，转移判定对建树方法很敏感。不过把全流程的结果放在一起看，差别不大：

- 1,265 个家族用 IQ-TREE、其余用 FastTree 时，三个毒力岛的召回率在校准权重下为 73% / 69% / 87%，默认权重下为 73% / 91% / 92%；纯 IQ-TREE 时分别为 65% / 66% / 82% 和 70% / 97% / 90%。
- 全基因组判定率也相近（O157 为 23.4%，纯 IQ-TREE 时为 22.8%）。

换建树方法就会变的判定，本身就不稳定，可以据此降权。

**结论**：在建树和批量同源搜索上，GPU 没有带来提速。真正的提速来自算法选择：搜索用 DIAMOND，建树用 FastTree。剩下的 3,260 个基因树用 FastTree 只花了约 10 分钟，用 IQ-TREE 按当时进度还要 3 小时以上。

GPU 真正派上用场的是结构这一步（`structure`，1,228 条“外部无同源”蛋白，中位长度 86 aa）：

| 步骤 | 耗时 |
|---|---|
| ESMFold 结构预测（A800） | 1,222 个结构 68 分钟，约 3.4 秒/个；16 个 CPU 上不现实 |
| MMseqs2-GPU 3 轮 profile 搜索，比对 1,842 万条 | 22 分钟 |
| Foldseek（CPU）建库，55 万个 AlphaFold Swiss-Prot 结构 | 约 1.5 分钟（直接读 tar） |
| Foldseek（CPU）结构检索 | 28 秒 |

Foldseek 在 CPU 上已经足够快，Foldseek-GPU 只在目标库大得多（如 AFDB50）时才有意义。

## 输出

- `hgt_events.tsv`：每行一个事件，按 `P_HGT` 降序排列。主要列：
  - `recipient` 和 `recipient_genes`：受体分支及其中的基因
  - `P_HGT` 和 `tier`：high 表示 ≥0.9，medium 表示 ≥0.6，low 表示 ≥0.3
  - `source`：`tree`、`clock` 或 `gain`
  - `p_direction`、`alt_recipient`、`alt_genes`：clock 事件专用。`P_HGT` 表示"这两个谱系交换过这个基因"的概率；`p_direction` 表示受体就是 `recipient` 的把握，0.5 代表方向无法判断；另一侧记录在 `alt_*` 中。tree 事件的 `p_direction` 恒为 1。
  - `donor1..3` 和 `p_donor1..3`：供体候选及其概率。gain 事件的 `donor1` 为 `unsampled`
  - 各项特征值、`flags`
- `hgt_genes.tsv`：每个基因取它所在的最佳事件。基因水平的 P 为 `P_HGT` × 该基因所在一侧为受体的概率（clock 事件按 `p_direction` 在两侧之间分配）。
- `summary.txt`：汇总信息；`species_tree.labeled.nwk`：带内部节点名的物种树。

**tree 模型的特征**（标准化系数为 v0.5 模拟数据上的校准结果）：

| 特征 | 含义 | 系数 |
|---|---|---|
| `ins` | 受体侧插入：在姐妹类群和外群中，侧翼相邻且中间为空位的比例；锚点取近缘种中也有的最近邻基因，跳过一起转移过来的邻居 | +1.43 |
| `f_T` | 随机打破平局时，出现"转入该受体分支"的调和所占比例 | +0.85 |
| `ctx` | 供体侧上下文偏移：受体拷贝与供体拷贝的邻域相似度，比该基因组对的平均水平低多少 | +0.84 |
| `recency` | 基因树距离相对于物种对背景距离的 −log 比值 | +0.80 |
| `comp` | GC 与 GC3 偏离，按受体枝年龄折减 | +0.63 |
| `near` / `contam` | 供体在姐妹类群内（建树误差风险）/ 真核污染嫌疑 | −0.62 / −0.48 |
| `copies` | 家族（拆分后的亚家族）平均每个基因组的拷贝数 | +0.55 |
| `me`、`f_opt`、`depth` | 移动元件 / 平局时偏向转移得到的频率 / log2(受体分支下的基因组数) | +0.43 / +0.37 / +0.33 |
| `dcost`、`alt` | 禁止转移时整个家族的代价增量 / 不允许任何转移进出该受体类群时 ML 树的代价增量 | −0.13 / +0.05 |

`copies` 的系数为正，是模拟器的特点：拆分之后仍是多拷贝的亚家族，大多来自近期重复或叠加型转移。真实数据中的多拷贝 tree 事件另有 `multicopy_family` 标记，可以据此再筛一遍。

**gain 模型的特征**（供体未采样）：

| 特征 | 含义 | 系数 |
|---|---|---|
| `comp` | 受体拷贝 GC、GC3 的稳健 \|z\| 均值，乘以 exp(−受体枝年龄/0.3)。外来序列的组成会逐渐向受体基因组靠拢（amelioration），所以组成偏离只对近期获得有说服力 | +1.77 |
| `site` | 在姐妹类群和外群中，侧翼相邻（干净空位）记 +，中间有别的家族的基因（替换或 orthogroup 拆分）记 − | +1.16 |
| `me` | 移动元件邻近（扣除基因组背景） | +0.71 |
| `g_len` | log2(基因长度 / 基因组中位数)。偏短意味着可能是假 ORF 或从头起源 | +0.45 |
| `g_alt`、`site_n` | 竖直遗传解释需要的丢失数 / `site` 的有效近缘种数 | −0.27 / +0.21 |
| `cotx` | 相邻基因也在同一节点获得的比例，减去该基因组的背景比例 | +0.10 |
| `g_size`、`g_para`、`g_patchy` | 每个基因组的拷贝数 / 获得的基因组中已有姊妹亚家族（旁系同源）的比例 / 类群内缺失比例 | +0.08 / −0.08 / −0.06 |

`g_para` 单独拟合时系数为 −0.57（拆分得到的旁系谱系大多是重复而非获得），但在联合拟合中它的信号被组成和空位检验吸收了。

`depth` 不在 gain 模型里：在 Yule 模拟树上它与 `g_alt` 高度共线，而真实树很不平衡（大肠杆菌菌株离根有十多个分支），学到的符号会外推错。

**clock 模型的特征**：`ins_n` +0.88、`dir` +0.80、`depth` +0.48、`clock`（−z）+0.44。这些系数只基于 9 个真阳性，不稳定。

**flags**：`possible_contamination`、`sister_clade_donor`、`weak_tree_support`、`insertion_site`、`recipient_locus_conserved`、`context_shift`、`co_transferred_block`、`mobile_element_nearby`、`donor_synteny`、`recent`、`clock_anomaly`、`direction_unresolved`、`composition_outlier`、`multicopy_family`（tree 事件所在家族每个基因组平均 ≥1.5 个拷贝，隐性旁系同源风险）；gain 事件另有 `unsampled_donor`、`clean_insertion_site`、`locus_occupied`、`short_orf`、`patchy`、`recurrent_gain`（同一家族在多个节点独立获得）、`paralog_present`（获得的基因组中已有姊妹亚家族）。

## 方法要点

0. **拆分旁系同源**（v0.5）：
   - 对平均每个基因组 ≥1.5 个拷贝的家族，在 ML 基因树上取重复加丢失代价最低的定根。
   - 两侧子树共有 ≥2 个物种、且至少占较小一侧物种数一半的节点视为古老重复，在此切开，切开的各部分作为独立的亚家族。
   - OrthoFinder 常把古老旁系同源并成一个 orthogroup（转运蛋白和调控蛋白超家族、整合酶）。整体调和时，旁系同源混在一起会变成高支持度的深层"转移"。
   - 只有一个多余拷贝（重叠为 1，例如单个基因组中的叠加型转移）不会切开。
   - 只对拷贝数高的家族切，是因为切开也会丢掉判断叠加型转移方向所需的原生拷贝。
1. **调和**：DTL 简约法（Bansal 等 2012），对物种维度做了 numpy 向量化，无根基因树的所有定根方式一次算完。物种树带时间时，只允许时间区间重叠的枝之间发生转移。对每棵树：随机打破平局得到 `f_T`；再做一次平局时偏向转移的回溯，得到 `f_opt`。
2. **分子钟检验**（ML 树）：
   - 对调和中每个物种形成节点，计算跨节点基因对的距离 ÷ 该物种对的全基因组背景距离，取上四分位数，再除以家族速率。家族速率取该家族各个直系同源节点的中位数。
   - 只检验**局部拓扑一致**的节点，即两侧各自覆盖其类群中所有含该家族基因的物种。基因树拓扑错误会伪造出"年轻"的节点，这一条是排除它的关键。
   - 对每个物种树节点，用所有家族的检验值算中位数和 MAD，得到 z 分数。z ≤ −2.5 的节点成为候选。已经被强 tree 事件解释过的基因不再检验。
   - 方向用外群插入检验判断：受体拷贝在外群中对应空位，供体拷贝在外群中对应保守位点。
3. **gain 候选**（v0.4）：
   - 对每个家族（包括没有基因树的小家族和单基因）在物种树上做 Wagner 式获得/丢失简约。获得代价等于转移代价（默认 3），丢失代价为 1。
   - 每个不在根上的获得节点生成一个候选，供体记为 `unsampled`。分布零散的家族（同源基因被远缘谱系各自获得，例如噬菌体、岛屿基因）会得到多个近期获得，而不是“一次很深的获得 + 大量丢失”。
   - 需要排除的解释有三种：竖直遗传后多次丢失、从头起源或假 ORF、orthogroup 拆分。
4. **替代代价 `alt`**：对每个 tree 事件，在 ML 树上重新调和一次，不允许任何转移进出受体类群（只禁止转入的话，方向反过来的转移代价相同），记录代价的增加量。
5. **合成与校准**：tree、clock、gain 各用一个逻辑回归。`calibrate` 命令按来源分别拟合；clock 事件只要任一侧与真值匹配就记为正例。gain 事件与真值的匹配方式和其他事件相同：同一家族，基因 Jaccard ≥ 0.5。

## 模拟数据上的结果（测试集，校准权重，阈值 P ≥ 0.6）

v0.4 起，模拟器在 v0.3 基础上增加了以下内容，所以数字与旧版本不能直接比较：

- 来自数据集以外谱系的转移：新家族，按块插入，常带移动元件。
- 假阳性来源：从头起源或假 ORF（偏短、偏 AT），以及 orthogroup 拆分（某个类群的拷贝被单独编成一个家族）。
- 序列组成：基因组 GC 沿物种树漂移，转入基因带着供体的组成，再按指数规律向受体靠拢。

### 分子钟检测的实际效果

以下分析基于 v0.3 的模拟器。结论：**检测是准的，但检出的事件很少**，对古老转移召回率的贡献只有 0–0.02。

- 在高分段（z ≤ −4），候选基本都是真实转移。三个测试集里，校准后被判定的 clock 事件共 2 个，都是真的；其中一个方向判断错误。
- 检出少的原因是信号比噪声弱。基因树上 log 比值的节点噪声约为 0.13–0.14。拓扑不可识别的古老转移，预期信号中位数只有 −0.25（原核）和 −0.12（混合），换算成 z 约为 −1.8 和 −0.9。只有 18–32% 的事件预期信号强于 −0.5。
- 很多转移保留了受体原有的拷贝（叠加型），节点两侧不是干净的物种形成，所以无法检验。
- 根节点两个子支之间的交换没有外群可参照，方向无法判断，`p_direction` 会接近 0.5。
- 真实数据中的速率异质性通常比这个模拟更大，所以分子钟方法在真实数据上只会更弱。它适合作为"值得人工复核的强候选"来源，不能指望靠它补回大批古老转移。

**为什么古老转移的召回率有上限**：原核测试集中，约 55% 转入祖先分支的转移，用真实基因树的拓扑也找不回来。这些转移的供体大多在姐妹谱系上，DTL 代价与"古老重复 + 丢失"完全相同，分子钟信号又大多淹没在速率噪声里。

## 真实数据：肠杆菌目 18 个基因组

数据：Ensembl Bacteria 的 18 个基因组，共 81,844 个蛋白编码基因，每个基因都有 CDS 组成。OrthoFinder 得到的家族中，有 4,523 个含 4–150 个基因，为它们建了基因树。物种树由 300 个单拷贝家族串联构建，拓扑符合预期：志贺菌嵌在大肠杆菌内部，柠檬酸杆菌是沙门菌的姐妹群。

扫描参数为 `--collapse 95 --composition`，旁系同源拆分默认开启，在 9 线程下每次约 50 秒。

- 563 个多拷贝家族被拆成 2,603 个亚家族，拆分后共有 6,282 个带基因树的家族。
- 共产生 7,148 个 tree 候选、5,316 个 clock 候选和 12,706 个 gain 候选。

运行命令：`examples/enterobacterales/scan.sh`；检验命令：`check_known_islands.py <workdir> <scan dir>`，结果在 `islands_{calibrated,default}.txt`。

**用文献中的毒力岛检验。** 岛按参考基因组坐标定义：SPI-1 和 SPI-2 用鼠伤寒沙门菌，LEE 用 O157。其他基因组中的对应拷贝，用基因树最近邻直系同源来找。

这里不能直接按 orthogroup 归属来找，因为 OrthoFinder 会把 SPI-1、SPI-2、LEE、ETT2、Ysa 的同源 T3SS 组件放进同一个家族。

三个岛的 GC 都明显低于所在基因组，与文献一致：

| 区域 | GC | GC3 |
|---|---|---|
| 鼠伤寒沙门菌全基因组 | 0.535 | 0.598 |
| SPI-1 | 0.454 | 0.465 |

各岛中被判为 HGT 的基因数（P ≥ 0.6），格式为“校准权重 / 默认权重”。“受体在预期节点”一列给出判出基因中受体落在预期节点上的个数，分母是判出的基因数：

|---|---|---|---|---|---|---|

**深层伪迹（v0.4 → v0.5，校准权重）。** 深层指受体为 N2–N7，即受体类群覆盖一半以上的基因组。

|---|---|---|

**全基因组判定率**（v0.5，校准权重）。P ≥ 0.6 的基因占全部基因的 2.4%（弧菌）到 23.9%。只计受体类群覆盖不到一半基因组的事件时：

- 大肠杆菌和志贺菌：11.8%（K-12）到 19.8%（福氏志贺菌）
- 沙门菌：9.1%（*S. bongori*）到 14.7%
- 克雷伯菌、肠杆菌、耶尔森菌、果胶杆菌：8.8–9.6%

作为参照，文献估计 K-12 自与沙门菌分开以来通过 HGT 获得的基因约占 18%（Lawrence & Ochman 1998）。O157 的 O-island 比 K-12 多出约 1,400 个基因（Perna 等 2001）。福氏志贺菌带有数百个 IS 拷贝，比例偏高并不意外。

结论：

1. **深层伪迹的主要来源是 orthogroup 把古老旁系同源并在一起，不是调和本身的平局。**
   - 典型例子：酒石酸转运蛋白，132 个基因，平均每个基因组 7.8 个拷贝；噬菌体整合酶 IntA，122 个基因。
   - 这些伪转移在 ML 树上是“必需”的：禁止转移进出受体类群后，代价增加的中位数为 4，而岛屿上的真实事件只有 1。所以收缩低支持枝和降权都去不掉它们。
   - 在古老重复处拆成直系亚家族后，深层 tree 事件减少 84%，剩下的绝大多数已不在多拷贝家族中。
2. **gain 候选补上了类群特有家族这一盲区。** SPI-2 和 LEE 的召回率在默认权重下保持在 90% 以上，受体大多在预期节点。
3. **拆分后，校准权重在 SPI-2 上的召回率下降了**（84% → 66%）。v0.5 模拟器中拆分产生的旁系谱系 gain 候选多数是阴性，校准时 gain 模型的截距因此下调，组成偏离中等、空位检验又不起作用的 SPI-2 基因就落到了阈值以下。默认权重下仍有 97%。
4. **SPI-1 仍有约一半放得太深**，因为它与 ETT2、Ysa 在不同的基因组中，物种重叠为零，按物种重叠拆不开。

**外部供体检索**（在 GPU 机器上完成；参考库为 5,285 个 UniProt 参考蛋白组、1,842 万条蛋白，其中哺乳动物 69 个）：

- 候选基因 7,325 个（P_HGT ≥ 0.6 的 gain 事件），属于 3,782 个事件。其中 975 个基因完全没有命中；另有 697 个的命中都在自身属内，或覆盖不到查询的 40%。
- 按相似性（前 10 个外部命中按 bit 分加权），供体类群依次为：
  - 肠杆菌目其他属：3,279 个基因
  - 外部无同源：1,672 个
  - 其他 γ-变形菌：1,433 个
  - 噬菌体（有尾噬菌体纲）：383 个
  - 其他变形菌门：171 个
  - 其他细菌：131 个
  - 芽孢杆菌门：122 个
  - 拟杆菌门、蓝细菌门、放线菌门：各约 30–40 个
  - 其他后生动物：18 个；真菌：6 个；古菌：3 个；哺乳动物：1 个
- 按系统发育：1,959 个事件有 ≥4 个外部同源序列，建树后离受体最近的类群为：
  - 肠杆菌目其他属：63%
  - 其他 γ-变形菌：22%
  - 噬菌体：3.8%
  - 其他变形菌门、其他细菌：各约 3%
  - 芽孢杆菌门：2.2%
  - 古菌 2 个，真菌 1 个，哺乳动物 1 个

  相似性与系统发育给出的类群一致率为 84%。
- **没有可信的哺乳动物来源基因。** 唯一落在哺乳动物附近的是 *S. arizonae* 中一个未注释的小蛋白，位于一串低 GC 的假定蛋白中。它只有 7 个外部命中，一致度约 24%，无法判断来源。另有 251 个基因有哺乳动物同源物，但它们最近的亲缘都是细菌，属于在各界都保守的家族。
- 真核参考蛋白组本身可能混有细菌污染。例如寄生性粘孢子虫 *Thelohanellus kitauei* 是 71 个基因的最佳外部命中，这很可能是其基因组组装中的细菌污染。因此单个真核物种的命中不能作为真核来源的证据，需要多个真核谱系一致。

**结构检索**（`structure`，对象是 1,228 个“外部无同源”事件）：

| 指标 | 结果 |
|---|---|
| ESMFold 平均 pLDDT ≥ 70 / 50–70 / < 50 | 31% / 33% / 36%；< 100 aa 的短 ORF 中，pLDDT < 50 的占 41% |
| 3 轮 profile 搜索找到外部同源 | 91 个（7.4%）：肠杆菌目其他属 39，其他 γ-变形菌 17，蓝细菌 6，拟杆菌 5，真核合计 11 |
| Foldseek 同折叠匹配（TM ≥ 0.5） | 117 个（9.5%），其中 73 个连 profile 搜索也找不到同源 |
| 按 pLDDT 分层的结构匹配率 | ≥ 70：25%；50–70：5%；< 50：1 个 |
| 结构类群（未过滤） | 肠杆菌目其他属 54，芽孢杆菌门 16，其他 γ-变形菌 14，其他变形菌门 8，哺乳动物 6，其他细菌 6，其余 ≤ 4 |
| 两种方法都有结果时，类群一致（未过滤） | 11 / 44 |

- **结构检索把“孤儿”分成了两类。**
  - 折叠良好（pLDDT ≥ 70）的蛋白中，有四分之一能找到同折叠的已知蛋白，多数在其他细菌中。
  - pLDDT < 50 的 442 个几乎都没有结构匹配。它们以短 ORF 为主，很可能是假 ORF 或无序肽段，不应当作 HGT 证据。
- **结构匹配给出的是折叠或功能，不是供体。**
  - 中位 TM 为 0.66，序列一致度大多只有 10–20%。
  - 与 profile 搜索的类群一致率只有 25%。
  - Swiss-Prot 本身偏向模式生物：哺乳动物占 11.8%，芽孢杆菌门占 12%。
- **仍然没有可信的哺乳动物来源。**
  - 哺乳动物为首位类群的 6 个事件（占 5%）低于哺乳动物在 Swiss-Prot 中的比例。
  - 其中 4 个是重复折叠：3 个锚蛋白重复，1 个 Ig 样 V 区；还有 1 个 TPR 重复（GPSM2）。
  - 剩下 1 个是 *Y. enterocolitica* 的 729 aa 蛋白，匹配真核丝氨酸/苏氨酸激酶结构域（肌球蛋白 III、NINAC，TM 0.78）。长度与已知的类真核激酶效应蛋白 YopO/YpkA 一致。
  - 这些是病原菌常见的“类真核效应蛋白”。它们可能很古老，也可能经过趋同，结构相似不能确定来源。另一个例子：*S. arizonae* 的一个蛋白匹配耶尔森菌 LRR 效应蛋白 YopM（TM 0.88）。
- **profile 搜索的真核命中同样来自重复结构。** 包括 LRR（IpaH 类效应蛋白）、卷曲螺旋、五肽重复、串联重复的假 ORF。迭代过程中 profile 会向这些家族漂移。

**重复过滤的效果**：

| 指标 | 结果 |
|---|---|
| 查询有 Pfam 结构域 / 有重复型 Pfam 结构域 | 194 / 33（共 1,228 个） |
| 查询有串联重复 / 卷曲螺旋 | 50 / 34 |
| 被命中的目标蛋白带重复型区域 | 21,022 / 37,563：其中 Pfam 18,532 个，另有 50,086 段串联重复和 5,235 段卷曲螺旋；扫描用时 299 s |
| profile 命中中重复驱动的比例（一致度 < 40%） | 24,085 / 38,027（63%） |

|---|---|---|
| `repeat-like`（不给供体） | — / 21 / 23 | — / 16 / 22 |

- **Pfam 去掉的，正是此前手工核对出的伪迹。**
  - profile 侧：IpaH 类 LRR 效应蛋白、五肽重复、MORN 重复、Sel1 和 TPR 蛋白。
  - 结构侧：3 个锚蛋白重复蛋白、TPR 蛋白（GPSM2）、IpaH 类和 YopM 类 LRR 效应蛋白，以及 Sel1/HcpC 类蛋白。
- **串联重复和卷曲螺旋检测去掉了 Pfam 漏掉的部分。**
  - profile 侧的两个脊椎动物“供体”：*E. fergusonii* 的串联重复假 ORF（pLDDT 36），*C. sakazakii* 的长卷曲螺旋蛋白（COILS 判 829 个残基中 47% 为卷曲螺旋）。
  - 结构侧：一个只剩 1 条命中的 TPR 糖基转移酶“脊椎动物”匹配；ArpA 类锚蛋白蛋白；一个匹配类 Rad50 卷曲螺旋的“古菌”事件；RTX 类溶血素。
- **一致度豁免救回了几例真同源。** 其中有 Sel1 蛋白（与 *Amoebophilus* 在 331 aa 上一致 51%，与 *Flammeovirga* 在 400–590 aa 上一致 44–50%），以及噬菌体尾部蛋白（与噬菌体 2H10 在 1,014 aa 上一致 44%）。这些蛋白当初被 DIAMOND 归为“外部无同源”，很可能是 DIAMOND 默认的重复屏蔽（tantan）屏蔽掉了重复区。所以“外部无同源”中有一部分只是重复蛋白，而不是真正的孤儿基因。
- **剩下的真核类群都不是重复折叠，但也都不足以说明真核来源。**
  - 结构侧 5 个：
    - 类真核激酶（*Y. enterocolitica*，YopO 类，按结构匹配哺乳动物，按 profile 匹配真菌）；
    - Ig 样 V 区（Pfam 把 Ig 归为普通结构域）；
    - DEAD 盒解旋酶（原噬菌体蛋白）；
    - 植物叶绿体的 PsbP 样蛋白和 UPF0603 蛋白，这两类在细菌（包括蓝细菌）中也有同源物。
  - profile 侧另有 1 个：与卵菌 *Globisporangium* 一致度 17%，pLDDT 45，证据很弱。

## 已知局限

- 旁系同源拆分只看物种重叠：同源但独立获得、分布在不同基因组中的系统（SPI-1 与 ETT2）拆不开；拷贝数低的家族不拆，其中的隐性旁系同源仍会留下少量深层伪迹。
- 剩下的深层事件（约占判出基因的四分之一）大多仍无法与“竖直遗传 + 早期丢失”区分，不应当作 HGT 证据。
- gain 只看家族的物种分布，不看基因座。外群本身的特有基因（`g_alt` = 1）无法判断。
- 校准完全依赖模拟器。组成偏离只来自外来供体、假 ORF 只是偏短、丢失按操纵子成块：这些假设会直接改变真实数据上的权重。校准权重与默认权重在毒力岛上的差异就是例子。
- 时间约束只检查两条枝是否共存，没有 ALE 那种全局时间一致性，也没有建模 ILS。
- 分子钟检验只用 ML 树和枝长，没有直接使用多序列比对的距离；家族内部的谱系速率变化会被误认为交换。
- `f_T` 的质量完全依赖输入的 bootstrap 树；目前没有做 AU 检验。
- 真核污染检查只看 contig 上的基因组成。
- 移动元件权重和供体打分的 γ 都是手设的；clock 模型的训练样本很少。
- 模拟器较简化：没有 ILS，没有序列层面的模拟，建树误差用随机 NNI 近似，没有长枝吸引。在本数据集里长枝吸引的信号也很弱：相对速率检验中，变形杆菌只比平均快 6%。
