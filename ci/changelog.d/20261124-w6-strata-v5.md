# W6: the report's identity strata derived again from the cells per table (protocol round1, version 11)

- `rel_w6_report` reads every stratum of the nearest identity in the strata of the evaluator it runs on (score
  version 5: a row counts as the nearest only if it covers at least half of row 0's stored target block; the tables
  whose other rows all cover less are `short_fragments_only`). The result rows carry the strata of the code that
  evaluated them, so the report derives the bins again from every arm's cells per held-out table (heldout_final.npz,
  heldout_best.npz, node_cells.npz), as score.aggregate forms them, wherever those cells give the rows' bits over all
  tables. A reading without such cells keeps its rows' bins only when they are of this version; otherwise it is left out
  and listed. No evaluation has to run again.
- The median coverage of the nearest row (score.nearest_coverage, coverage_by_stratum) stands beside every stratum:
  the table by the nearest identity, what relatives are worth by bin, and the pairs by bin. It is taken over the
  tables each reading scored.
- Baselines whose rows are of an older strata version (no cells per table) keep their bins under a labelled column,
  "<baseline> (strata v4)", with a caveat that their 0.9–1.0 bin mixes short end fragments with near relatives.
- report.json `strata`: the version, the readings derived from cells, those left out, and the baselines' versions.
